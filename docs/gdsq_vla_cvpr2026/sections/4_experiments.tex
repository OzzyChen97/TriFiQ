\section{Experiments}
\label{sec:experiments}

\subsection{Experimental Setup}
\label{sec:setup}

\paragraph{Benchmark and policies.}
We evaluate GR00T N1.5 and $\pi_{0.5}$~\cite{intelligence2025pi05} on the RoboCasa365 v1.0.1 target split~\cite{nasiriany2026robocasa365}. The benchmark has 18 Atomic-Seen, 16 Composite-Seen, and 16 Composite-Unseen tasks. GR00T uses the corresponding 60k-step post-training checkpoints; $\pi_{0.5}$ uses its RoboCasa checkpoint. Four atomic tasks---OpenCabinet, OpenStandMixerHead, PickPlaceDrawerToCounter, and CoffeeSetupMug---form the predeclared GR00T ratio-development set. The $\pi_{0.5}$ allocation transfers the frozen 16:1 ratio and performs model-specific functional adjudication and calibration; it does not tune the ratio from $\pi_{0.5}$ test rollouts.

\paragraph{Configurations and budgets.}
The final configuration is \method plus the frozen v8 runtime selector. The selector chooses the uncorrected GDSQ mask for GR00T and OHB for $\pi_{0.5}$. Static GDSQ, ATM, OHB, and ATM+OHB are ablations, not alternative definitions of ours. FP16 is the uncompressed reference. QuantVLA W4A8~\cite{zhang2026quantvla} is retained as a secondary low-bit comparison because its compression rate differs from ours. The direct budget controls are uniform W6, a search-matched random W4/FP16 mask, and an action-only allocator. Random search uses the same 26 candidates, functional-evaluation count, and seven development representatives as GDSQ; its seeds and masks are frozen before held-out rollouts. All masks obey the same uniform-W6 candidate-byte ceiling and use the same checkpoint, A8 calibration strategy, and guards.

\paragraph{Rollout and statistics.}
Every formal configuration uses 50 seeds per task, official horizons, a fresh rendered environment, four denoising steps, and 16 executed actions per replan. Initial action noise is deterministically keyed by $(\text{task},\text{seed},\text{replan})$, giving paired policy comparisons without changing the marginal normal distribution. We report task-macro SR, 10,000-draw task-cluster bootstrap intervals, paired task-level sign-flip tests, and Holm correction over preregistered contrasts. A no-guards crash, NaN, or out-of-range action is a formal failure rather than a silently dropped episode.

\paragraph{Claim--evidence gate.}
Each run manifest binds checkpoint, plan, calibration, selector, launcher, evaluator, environment, task list, and seed coverage by SHA-256. Each result row records its server-metadata hash and, when applicable, selector SHA, rule, variant, and configuration ID. The main table is generated from the evidence registry; a task-set cell remains pending unless its declared coverage is exact, duplicates are absent, statistics are reproducible, and source drift has an explicit audit. Replay audits retain the frozen launch manifests: they reconstruct every task/seed key and must reproduce the registered summary exactly before later source edits can be disclosed without invalidating immutable result rows. This gate is passed by the completed $\pi_{0.5}$ four-configuration matrix, the three-manifest GR00T uniform-W6 evaluation, and the independently complete GR00T $\Omega$-QVLA Atomic subset.

\paragraph{External Table~1 reproduction.}
For $\Omega$-QVLA~\cite{wang2026omegaqvla}, we pin the authors' code commit but rebuild task-set-specific W4A4 packs from frozen RoboCasa365 calibration data because the released LIBERO packs cannot be transferred. Table~\ref{tab:main_results} exposes independently gated task-set cells: the GR00T Atomic subset is complete, whereas its Composite cells and all $\pi_{0.5}$ cells remain pending. Table~\ref{tab:omega_qvla_libero} separately uses the same five configurations as Table~\ref{tab:main_results}---FP16, QuantVLA W4A8, Uniform W6, $\Omega$-QVLA W4A4, and ours---under the original LIBERO protocol: four suites, ten tasks per suite, ten held-out trials per task, and eight denoising steps. We import no author-reported values; all 4,000 local episodes must pass the joint manifest gate.

\subsection{Selector Validation}
\label{sec:selector_validation}

The path-equivalence test uses 256 frozen observations per model, four denoising steps, and paired noise. GR00T compares the selector's baseline decision with static GDSQ; $\pi_{0.5}$ compares the selector's OHB decision with static OHB. Both comparisons are bitwise equal on all $256/256$ action tensors, with maximum absolute difference zero and no non-finite output. This passes the preregistered reuse gate for the completed GR00T static 50-task run. It does \emph{not} authorize reuse of a partial $\pi_{0.5}$ OHB diagnostic, so we run a separate formal 50-task selector evaluation for $\pi_{0.5}$.

Before formal evaluation, a two-task, two-seed closed-loop preflight verifies four complete episodes and all row-level attestations; this preflight is diagnostic only. The $\pi_{0.5}$ manifest is then frozen before the first official rollout and specifies exactly 2,500 unique task/seed keys. \PiSelectorRunStatus\ All 2,500 rows select OHB and attest the frozen selector SHA; no task metadata or runtime outcome enters the decision.

\paragraph{GR00T final selector.}
By bitwise reuse, the final GR00T selector obtains 69.0\%, 40.6\%, and 40.4\% task-macro SR on Atomic, Composite-Seen, and Composite-Unseen, respectively, for 50.8\% over all 50 tasks. FP16 obtains 55.1\%; the paired all-task difference for ours minus FP16 is $-4.32$ points with a 95\% task-cluster interval of $[-6.56,-2.08]$. The QuantVLA configuration obtains 30.4\%, and ours exceeds it by 20.3 points with interval $[16.9,24.0]$. Because QuantVLA compresses the studied scope by 2.22$\times$ while ours compresses it by 1.99$\times$, this is a descriptive secondary comparison, not evidence that the selection signal is superior at fixed storage.

The completed uniform-W6 control obtains 68.4\%, 42.9\%, and 41.8\% on the three task groups, for 51.7\% overall at 1.80$\times$ theoretical compression. Ours is $-1.0$ point relative to W6, with a paired 95\% task-cluster interval of $[-3.1,1.2]$, while using 1.001 rather than 1.109 GiB in the candidate Linear scope. We therefore treat the GR00T fixed-ceiling comparison as competitive storage--accuracy evidence, not superiority.

\paragraph{$\Omega$-QVLA partial RoboCasa365 evidence.}
The completed GR00T Atomic evaluation contains exactly 900 episodes---18 tasks with 50 paired seeds each---and no formal failure. $\Omega$-QVLA obtains 60.1\% task-macro SR, with a 95\% task-cluster interval of $[50.7,68.7]$. Its theoretical tightly packed Linear-component size is 0.599 GiB, or 3.33$\times$ relative to the same 1.993-GiB FP16 scope. Composite-Seen, Composite-Unseen, and the 50-task mean remain pending, so this subset does not support an all-task ranking.

\paragraph{$\pi_{0.5}$ final selector and architecture boundary.}
\PiSelectorResultStatus\ The selector also exceeds QuantVLA W4A8 by 2.6 points (95\% task CI $[0.9,4.5]$, Holm-adjusted $p=0.023$), but QuantVLA has a different 2.96$\times$ compression rate and remains a secondary comparison. The three task-group SRs of the final selector are 57.8\%, 17.0\%, and 3.9\%, yielding 27.5\% over all 50 tasks at 2.20$\times$ theoretical candidate-component compression.

The uncorrected static mask obtains 25.3\%, while static ATM+OHB reaches 26.6\% as an ablation. The selector's significant gain over the same frozen mask isolates the value of admitting OHB for this model; it does not establish that the allocation is universally superior. We therefore report $\pi_{0.5}$ as an architecture boundary: runtime correction helps the transferred allocation, while fixed-budget superiority remains unproven.

\paragraph{Same-budget causal controls.}
Uniform W6, shown in both main tables, isolates whether mixed precision helps under the same byte ceiling. Random masks control candidate count, functional-search budget, and retained FP16 bytes. The action-only allocator tests whether paired behavioral sensitivity alone explains the selected layers. The result-blind functional screens for both search controls are complete, but their closed-loop development selection and formal held-out rollouts are not. These two search-mechanism controls remain supplemental because they answer causal questions rather than define deployable headline configurations; they will be reported only after complete audited manifests. \subsection{Ratio Stability and Component Tests}
\label{sec:ratio}

The frozen point rule selects CKA:CS$=16{:}1$ at 80.5\% development SR. Post-freeze hierarchical task/seed bootstrap gives it the largest fractional best probability (0.486), but every alternative's paired interval against 16:1 includes zero. Leave-one-task-out selects 16:1 on three omissions and ties it with 256:1 on the fourth. We therefore describe a broad ratio plateau rather than sharp 16:1 optimality. The ratio table, selection-controlled Primary-14 comparison, and earlier five-seed signal diagnostic are moved to the supplement. The new 50-seed component matrix---CKA-only, CS-only, $w_i=1$, no guards, and no functional adjudication---is preregistered on GR00T Primary-14; incomplete cells cannot replace those older diagnostics.

\subsection{Storage and Runtime Scope}
\label{sec:runtime}

\input{tables/efficiency}

The GR00T final plan stores an estimated 1.001 GiB over the LLM+DiT Linear scope, versus 1.993 GiB for FP16, giving 1.99$\times$ theoretical compression. The $\pi_{0.5}$ plan stores 1.868 GiB versus 4.113 GiB. The GR00T $\Omega$-QVLA estimate is 0.599 GiB and additionally includes its required DiT permutation indices and per-step A4 scale tables. These estimates include tightly packed low-bit weights, weight scales, block rotations, and native FP16 for protected layers and biases. They exclude the vision stack, activations, CUDA workspaces, and simulator state. The current $\Omega$-QVLA evaluation artifact is a 6.41-GiB dequantized FP16 pack with dense rotations; it validates the W4A4 numerical path but is not the packed-deployment size reported in Table~\ref{tab:main_results}.

The current execution path is eager fake quantization: it retains floating-point weights and executes floating-point GEMMs. On GR00T it therefore takes 0.254 seconds per replan and peaks at 17.7 GiB, compared with 0.139 seconds and 12.8 GiB for FP16. We make no latency or live-memory compression claim. Packed checkpoint size, isolated batch-1 policy-server latency, and process memory will be reported separately; end-to-end deployment gains require fused INT4/INT8 kernels.
