\subsection{Ratio Sweep and Stability}

The point-selection rule freezes 16:1 because it has the largest development task-macro SR. A separate post-freeze analysis resamples tasks and then paired seeds for 10,000 draws. No alternative ratio has a paired difference interval against 16:1 that excludes zero: for example, the 256:1 interval is $[-6.5,5.0]$ points and the CKA-only interval is $[-10.0,3.5]$ points. \subsection{Static Correction Ablation}

On the complete GR00T 50-task matrix, static ATM+OHB changes task-macro SR from 50.8\% to 49.4\%; the paired interval $[-3.28,0.52]$ points includes zero. On the complete $\pi_{0.5}$ static matrix, ATM+OHB changes 25.3\% to 26.6\%, while the preregistered held-out interval $[-0.39,3.13]$ and Holm-adjusted $p=0.542$ do not establish a gain. Neither combined configuration is an allowed output of the v8 selector. Standalone ATM and OHB remain static ablations; only the selector-chosen OHB runtime path populates the final row, and it does so through a separate complete 2,500-episode manifest.

\subsection{Eager Fake-Quant Runtime Diagnostic}

The GR00T final plan stores an estimated 1.001 GiB over the LLM+DiT Linear scope, versus 1.993 GiB for FP16, giving 1.99$\times$ theoretical compression. The $\pi_{0.5}$ plan stores 1.868 GiB versus 4.113 GiB. The GR00T and $\pi_{0.5}$ $\Omega$-QVLA estimates are 0.599 and 1.307 GiB, respectively, and additionally include required permutation indices and A4 scale tables. These estimates include tightly packed low-bit weights, weight scales, block rotations, and native FP16 for protected layers and biases. They exclude the vision stack, activations, CUDA workspaces, and simulator state. The current GR00T and $\pi_{0.5}$ $\Omega$-QVLA evaluation packs are 6.41 and 34.97 GiB because they store dequantized FP16 weights and dense rotations; they validate the W4A4 numerical path but are not the packed-deployment sizes reported in Table~\ref{tab:main_results}.

\input{tables/efficiency}

These measurements diagnose the current implementation rather than support a deployment claim. The eager path retains floating-point weights and executes floating-point GEMMs. On GR00T it takes 0.254 seconds per replan and peaks at 17.7 GiB, compared with 0.139 seconds and 12.8 GiB for FP16. Packed checkpoint size, isolated policy-server memory, and batch-1 latency require fused low-bit kernels.
